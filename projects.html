01 · COMPUTATIONAL PHYSICS

Percolation & network modelling

A computational study of phase transitions in two-dimensional percolation, comparing direct Monte Carlo sampling with the Newman–Ziff algorithm for tracking connectivity efficiently.

THE QUESTION

Percolation provides a simple model for how global connectivity can emerge from local randomness. I investigated how spanning clusters form on finite square lattices as the occupation probability increases, and how efficiently this transition can be resolved computationally.

THE ALGORITHMS

I first implemented direct Monte Carlo sampling using breadth-first search to test whether independently generated lattices contained a top-to-bottom spanning cluster. I then implemented a union–find data structure with path compression and union by rank, and used it to build the Newman–Ziff algorithm.

NEWMAN–ZIFF

Rather than regenerating a lattice for every occupation probability, the Newman–Ziff method occupies sites incrementally in random order and dynamically updates connected components. I tracked spanning behaviour and largest-cluster size after every occupation step, then used binomial convolution to recover observables as continuous functions of occupation probability.

RESULTS

The simulations reproduced the characteristic sharpening of the percolation transition with increasing lattice size, with spanning probability curves intersecting near p ≈ 0.593, consistent with the critical probability for site percolation on a square lattice. Timing experiments also showed the computational advantage of Newman–Ziff over repeated BFS sampling, particularly as the resolution in occupation probability was increased.

WHAT I LEARNT

The project connected statistical physics with practical algorithm design: graph traversal, disjoint-set data structures, Monte Carlo methods, numerical convolution and empirical complexity analysis. It also showed how choosing the right representation of a problem can remove large amounts of repeated computation.

02 · RESEARCH SOFTWARE

MatterApp — HPC research tooling

MatterApp is a Python desktop application I built to simplify computational materials workflows across local and remote HPC systems.

THE PROBLEM

Working with remote HPC systems often involves switching between terminals, file-transfer tools, visualisation software and separate analysis scripts. I wanted to bring those repetitive steps into a single interface and make common research workflows easier to manage.

WHAT I BUILT

I developed a PySide6 desktop application that connects to remote HPC systems over SSH and SFTP, provides an integrated remote file browser, and supports interactive two-factor authentication. Remote structures, images and analysis files can be accessed directly from the application.

SCIENTIFIC ANALYSIS

The application also includes tooling for VASP workflows, including run classification, convergence checks, magnetisation extraction, structure inspection and analysis of PROCAR band and orbital data. These tools turn raw simulation outputs into more immediately useful summaries and visualisations.

TECHNICAL FOCUS

The project combines GUI development, remote authentication, asynchronous behaviour, file-system handling and scientific data processing. It also required separating the application into components for connection management, file browsing, parsing, analysis and visualisation.

TOOLS

Python · PySide6 · Paramiko · NumPy · Matplotlib · ASE

FOCUS

03 · ENERGY & QUANTITATIVE MODELLING

Power price modelling

A forecasting project exploring how temporal behaviour, recent market conditions and electricity-system fundamentals can be combined to model regional power prices.

THE PROBLEM

Electricity prices depend on a mixture of recurring temporal patterns, local system conditions and rapidly changing supply-and-demand dynamics. I worked on building a modelling pipeline that could transform these different sources of information into features suitable for price forecasting.

FEATURE ENGINEERING

I constructed temporal features including hour, weekday, month and weekend indicators, alongside lagged observations of price and system load. I also created features describing renewable generation, renewable share of demand and residual non-renewable demand to capture interactions between generation mix and market conditions.

MODELLING PIPELINE

The workflow separated numerical and categorical variables and used a preprocessing pipeline with standardisation and one-hot encoding before model fitting. Rather than fitting a single global model, I also implemented separate models for individual market areas to allow regional behaviour to be represented independently.

EVALUATION

Models were trained on an earlier time period and evaluated on held-out later data using root mean squared error, both overall and at individual area level. This provided a simple way to compare in-sample fit with genuine out-of-sample forecasting performance.

WHAT I LEARNT

The project gave me practical experience building a complete predictive modelling workflow: understanding raw market data, designing features, preventing temporal information leakage, constructing reusable preprocessing pipelines and evaluating models on unseen data.

04 · PROBABILITY & DECISION MODELLING

Blackjack strategy engine

A playable Blackjack environment paired with a recursive strategy engine that evaluates hit and stand decisions using expected value.

THE PROBLEM

Blackjack is a useful decision-making problem because each action can be evaluated probabilistically. I wanted to go beyond simply implementing the game and build an engine that could quantify the expected outcome of different decisions from any player and dealer state.

EXPECTED-VALUE ENGINE

I modelled dealer outcomes recursively, exploring every possible sequence of dealer draws until a terminal state was reached. These outcome probabilities were then used to calculate the expected value of standing for a given player hand.

OPTIMAL DECISIONS

To evaluate hitting, the engine considers every possible next card and recursively analyses the resulting hand. At each future state, it chooses the action with the higher expected value, allowing the original hit decision to incorporate optimal subsequent play.

MEMOISATION & STRATEGY CHART

Because many game states are encountered repeatedly, I cached previously calculated dealer distributions and hit/stand expected values. The engine can generate a complete strategy table for hard and soft hands and serialise the resulting decisions and expected values for reuse.

INTERACTIVE GAME

I integrated the strategy engine into a Pygame Blackjack interface with animated dealing, card flipping and resizable layouts. During play, the application displays the recommended action alongside the expected values associated with the available decisions.

WHAT I LEARNT

The project gave me practical experience with recursive probability models, expected-value optimisation, state caching and separating decision logic from an interactive application. It also provided a simple environment for thinking about sequential decisions under uncertainty.
